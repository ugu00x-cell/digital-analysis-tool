## 結論：15年ゴリラをやっていた

結論から書く。
私は製造業の現場で15年間、ゴリラをやっていた。

高専時代はアセンブラやC/C++でPID制御を書き、高専ロボコンで全国ベスト4まで行った。
その人間が就職してから15年、プログラミングからほぼ離れて、NCプログラムと品質管理で現場を回していた。

測って、叩いて、直す。
データを見て、不良を潰す。
力技で詰めていく日々。これをゴリラと呼ぶ。

そのゴリラが、Pythonを独学で再起動して、生成AIのAPIを叩き始め、今はClaude Codeに丸投げしている。
**AIで武装したゴリラ、略してAIゴリラ**だ。

Findy Pythonの偏差値は63。まあまあだ。

この記事は、製造業でゴリラをやっていた人間が、AIゴリラに進化するまでの記録である。

## スキル変遷の時系列

時系列で並べると、こうなる。

| 時期 | 道具 | 状態 |
|---|---|---|
| 高専時代 | アセンブラ、C/C++ | 技術者の卵（全国ベスト4） |
| 就職〜5年 | NCプログラム、治具設計 | **ゴリラ期（加工技術）** |
| 5年〜15年 | Excel、測定器 | **ゴリラ期（品質管理）** |
| 再起動 | Python独学 | 道具を思い出すゴリラ |
| ここ数年 | GAS / n8n / Dify | 道具を使い始めたゴリラ |
| ここ1〜2年 | Looker Studio | 可視化できるゴリラ |
| ここ1年 | Claude / Gemini API | AIを叩くゴリラ |
| 現在 | バイブコーディング（Claude Code） | **AIゴリラ** |

高専時代は技術者だった。でも就職してからの15年で、プログラミングの筋肉はほぼ錆びた。
そこからの再起動が、この記事の本題だ。

## 高専時代：技術者の卵だった

最初だけ書いておく。

高専では制御情報工学科にいた。
卒業研究はPID制御＋GPSリアルタイム処理で動く全自動芝刈り機。
高専ロボコンではステアリング制御を担当し、電子回路を組み、C言語とアセンブラでマイコンを動かしていた。

当時は、自分のことを技術者だと思っていた。
これから10年プログラミングから離れるなど、想像もしていなかった。

## ゴリラ期（加工技術5年）：コードから手が離れた

就職先は工作機械メーカー。最初の配属は加工技術部だった。

仕事はNCプログラムの作成、工程設計、治具設計。
NCプログラムは書くが、アセンブラやC言語とは別物だ。
G00、G01、M30の世界。プログラミングというより「加工の手順書」だ。

ここでプログラミングの筋肉は半分くらい落ちた。
でも、別の筋肉が育った。

- どの工具が、どの材料を、どのくらいの速度で削れるか
- どこに治具を当てれば、部品が動かないか
- どの工程順なら、精度が出るか

**「現場でモノを作れる」感覚**が5年でインストールされた。
コードは書かなくなったが、製造業の身体性が身についた時期だ。

## ゴリラ期（品質管理10年）：データとにらめっこ

次の10年は品質管理部。
完成品検査、Cpk管理、不良解析、データ分析。

ここで何をやっていたかというと、

- 測定データをExcelに貼り付ける
- グラフにして傾向を見る
- 規格外が出たら、原因を遡る
- 対策書を書く

これを毎日やっていた。
やっていたことはデータサイエンスそのものだが、当時はそう呼んでいなかった。
「品質管理の仕事」と呼んでいた。

10年続けて、あるとき気づいた。
**Excelでやっているこの作業、Pythonなら10秒で終わるのでは？**

## 再起動：pandasとの再会

Pythonを独学で始めたのは、楽をしたかったからだ。

不良データのCSVを集計するのに、Excelで数時間かけていた。
それをpandasで書いたら10秒で終わった。
10秒で終わるものに数時間かけていた過去の自分が、急に悲しくなった。

ここから雪崩のように再起動が始まった。

- 集計したい → pandas
- グラフにしたい → matplotlib
- Cpk計算 → scipy
- Slack通知 → requests

気づいたら、業務のほとんどをPythonで自動化していた。
15年錆びていた筋肉が、ゆっくり動き始めた感覚だった。

## 道具を使い始めたゴリラ：GAS / n8n / Dify

Pythonで自動化を進めると、次は「Pythonすら書きたくない作業」が出てくる。

- Googleスプレッドシートの定期更新 → GAS
- 複数サービスの連携 → n8n（ノーコード自動化ツール）
- AIワークフロー → Dify（LLMアプリ構築プラットフォーム）

このあたりで、「コードを書く」から「部品を組み合わせる」にシフトした。
ゴリラが道具を使いこなし始めた段階だ。

n8nでスクレイピング→Gemini要約→Slack通知、という流れが30分で組める。
15年前の自分なら丸1日かかっていた作業だ。

## AIを叩くゴリラ：副業の武器になった

生成AIのAPIが使えるようになって、副業案件が一気に変わった。

納品済みの案件を並べるとこうなる。

- GAS × Claude API 営業メール自動生成システム
- GAS × Gemini API パーソナライズDM自動生成
- Python × Claude API 請求書PDF自動読み取り→Excel集計
- 12万点商品DB対応のRAGチャットボット
- LINE × Gemini API チャットボット

技術的に難しいことはしていない。
AIのAPIを叩いて、業務を自動化するだけ。

ここで製造業15年のゴリラ期間が効いた。
現場の業務フローが身体でわかるから、「ここをAIで置き換えられる」が直感で見える。
エンジニアだけでは気づけないポイントが、ゴリラには見える。

**ゴリラ期間は無駄ではなかった。むしろ、今の武器になっている。**

## AIゴリラの誕生：バイブコーディング

そして今、私はコードを手で書いていない。

Claude Codeに指示を出し、AIがコードを書き、実行し、結果を返す。
私は結果を見て、次の指示を出す。
これをバイブコーディングと呼ぶらしい。

```
私：「M5StickC Plus2の加速度データを5秒ごとにFastAPIに送りたい。
     Arduino IDEでコードを書いて」
Claude Code：[コード生成・動作確認]
私：「次は受信側。FastAPIでデータを保存して、FFTで周波数分解。
     異常があればSlackに飛ばして」
Claude Code：[マイクロサービス3つ構築・動作確認]
```

ゴリラがAIで武装した。**AIゴリラ**の誕生だ。

力技の試行錯誤は残っている。
動くまで試す。このゴリラ的な体力は、製造業15年で育ったものだ。
違いは、試行錯誤をすべてAIに委ねていること。
ゴリラは指示を出すだけで、手は動かさない。

## 今やっていること：中小製造業向け予知保全プロダクト

この15年のゴリラ期間＋AIゴリラの武装を全部使って、今プロダクトを作っている。

**コンセプト：** 数千万円する予知保全ソリューションを、汎用技術の組み合わせで数千円で再現する。

### 技術スタック

| レイヤ | 採用技術 | 単価 |
|---|---|---|
| センサー | M5StickC Plus2 / CoreS3（3軸加速度センサー内蔵） | 約4000円/台 |
| 通信 | Wi-Fi + HTTP POST | 無料 |
| バックエンド | FastAPI（3マイクロサービス：収集・分析・通知） | 無料 |
| 分析 | FFT + エンベロープ解析 + Z-score異常検知 | 無料 |
| 通知 | Slack Webhook | 無料 |

ハードウェア込みで1台あたり数千円。
大手ベンダーの数千万円ソリューションと、同じことをやる。

### 検証データセット

公開されている4つのベンチマークで精度を詰めている。

- **CWRU**（Case Western Reserve University）：人為損傷データ。教科書レベル
- **NASA/IMS**：自然劣化の7日間連続運転データ
- **XJTU-SY**：運転条件が変わるデータ。条件間転移が難しい
- **FEMTO**：個体差が大きい17個のベアリング

このあたりは別記事で詳しく書いた。
→ [製造業エンジニアがベアリング異常検知をゼロから実装した話]

## なぜ「低コスト再現」なのか

中小の工場に入ると、現実がわかる。

大手ベンダーの予知保全システムは、初期費用で数百万〜数千万円かかる。
導入だけで中小の設備投資枠を食い潰す。
結果、「壊れてから直す」モードから抜け出せない。

でも、やっていることの本質は単純だ。
**振動を測って、周波数分解して、異常を検知する。**

これだけなら、M5Stick＋FastAPI＋Pythonで成立する。
高いのはソリューションそのものではなく、パッケージ化と営業コストだ。

だから、作れば勝てる場所がある。
現場がわかって（15年のゴリラ期間）、AIに投げる判断ができる（AIゴリラ化後）人間にしか、この組み合わせはできない。

## ゴリラ期間は財産になった

20年の変遷を振り返って、気づいたことがある。

**プログラミングから離れていた15年は、無駄ではなかった。**

高専で身につけた技術者としての芽が、現場の15年でゴリラとして鍛えられ、AIで武装した今、両方が同時に効いている。

- アセンブラで殴っていた試行錯誤の感覚 → バイブコーディングの指示出しと同じ
- 品質管理で異常値を見つける感覚 → Kaggleで特徴量を作る感覚と同じ
- 現場の業務フローを読む感覚 → AIをどこに刺すかを見つける感覚と同じ

ゴリラ期間がなければ、今のAIゴリラはいない。
技術者のまま15年やっていたら、製造業の身体性は身につかなかった。

**コードを書かない15年があったから、今コードを書かせる側に回れる。**

皮肉なようだが、これがキャリアというものだと思う。

## まとめ

- 高専時代：技術者の卵（ベスト4）
- 製造業15年：ゴリラ期間（現場で鍛えられた）
- Python独学〜現在：ゴリラの武装が始まった
- 今：AIゴリラ（バイブコーディングで予知保全プロダクト開発中）

道具は変わったが、ゴリラはゴリラのままだ。
違いは、武器がアセンブラからClaude Codeに変わったこと。
ゴリラ期間で鍛えた「現場で動くもの作る」筋肉は、AI時代に一番効く。

次の5年でまた別のゴリラに進化していると思う。楽しみだ。
